ADR Regression Experiment Report

Full experiment plan and results for predicting Average Daily Rate on the City Hotel H2 dataset: preprocessing with documented column truncation, sixteen-by-three run matrix across model families, every run logged, and explicit conclusions on the pipeline and model selection.

Target: ADR (average daily rate)
Dataset: data/raw/H2.csv
Output dir: outputs/results/regression
Seed: 42 · Test split 0.2 · Log: runs.csv + per-run JSON

What was built

Two new modules under src/hotel_booking/regression/:

  • pipeline.py — deterministic preprocessing with documented column pruning, date reconstruction, invalid-row rules, ordinal + one-hot encoding, and per-run log dicts.
  • run.py — 10 model families × 3 preprocessing variants = 19 runs; logs to JSON + runs.csv; writes conclusions.md.

How to run it

Install the project and deps once, then run the matrix:

pip install -e .
python -m hotel_booking.regression.run

Or via CLI:

python -m hotel_booking.cli regression \\\n --data data/raw/H2.csv \\\n --out outputs/results/regression

Model families imported

All runs use scikit-learn:

  • Linear: LinearRegression, Ridge, Lasso, ElasticNet
  • Nonlinear / ensembles: DecisionTreeRegressor, RandomForestRegressor, GradientBoostingRegressor, SVR(rbf)
  • Neural nets: MLPRegressor (small and deep)

Data preprocessing pipeline

Prediction is treated as booking creation. That is what drives the leakage cuts below and is recorded in each run log.

Columns dropped with reasoning

ColumnReason
ReservationStatusDirect post-booking outcome; in this CSV it agrees exactly with IsCanceled.
ReservationStatusDatePost-booking timestamp; leakage for a booking-time ADR estimate.
ArrivalDateWeekNumberReconstructed into a single arrival date, so this part is redundant after rebuild.
CompanyAlmost entirely empty ID field; not meaningful for rate.

Invalid-row exclusions with reasoning

RuleReason
total_guests <= 0Not a valid booking.
total_nights <= 0Length of stay is zero, so ADR is not meaningfully defined.
Babies in {9,10}EDA outlier rule from the existing EDA notebooks.
Adults == 0EDA outlier rule, consistent with the existing cleaning code.

This removes 656 rows from the 79,330-row H2 file, leaving 52,645 rows.

What is kept and how it is encoded

  • Numeric — LeadTime, arrival_days, StaysInWeekendNights, StaysInWeekNights, Adults, Children, Babies, IsRepeatedGuest, PreviousCancellations, PreviousBookingsNotCanceled, BookingChanges, DaysInWaitingList, RequiredCarParkingSpaces, TotalOfSpecialRequests
  • Ordinal — Meal, MarketSegment, DistributionChannel, ReservedRoomType, AssignedRoomType, DepositType, CustomerType
  • One-hot — Country (top 15 + Unknown + Other folded), plus the same categorical fields one-hotted

Final feature count per run: 74 — 14 numeric + 7 ordinal + 53 one-hot. The exact list is recorded inside each run JSON.

ADR == 0 handling. Kept by default, because the business meaning of zero-rate bookings is unresolved in the project docs. A drop_adr_zero=True variant is also run so the effect can be measured directly. Default pipeline keeps 801 ADR==0 rows.

Conclusions from the runs

These conclusions are about this preprocessing pipeline and these model defaults, compared across a single seed-42 split. They are not yet a tuned production model.

  1. Tree ensembles are clearly ahead of linear models for this raw ADR setup. RandomForest and GradientBoosting both beat every linear variant in RMSE and R². The gap points to nonlinear interactions in the categorical and booking features mattering for rate.
  2. Regularization did not help much once the feature set was fixed. Ridge ≈ OLS, and Lasso / ElasticNet were worse. The linear signal looks relatively stable; the bigger issue is missing nonlinear structure, not overparameterized linear fits.
  3. Log1p(target) did not improve this setup. Best no-log run: 54.59; best log run: 55.37. Predicting ADR in original units worked better than predicting log-ADR and back-transforming, for these models and this feature set.
  4. ADR==0 dropping barely moved the needle. Best keep-zero run: 54.59; best drop-zero run: 54.72. On this cleaned slice, the zeros are not driving the comparison. The main gains come from model family and feature encoding, not from removing zeros.
  5. SVR and MLPs are not worth chasing further in this form. They did not beat RF / GB and cost more in fit time. If nonlinear gains are the goal, the tree families are the better first place to tune.
Validation note. The run matrix was re-executed and re-read from outputs/results/regression/runs.csv and a sample run JSON to confirm the log is complete and the numbers are reproducible. The best run label is rf_adr0_keep.

What would tighten this further

  1. Replace the fixed split with CV inside the runner so model selection is not tied to one split.
  2. Add a tuned RF / GB variant so the “nonlinear wins” conclusion is tested against tuned baselines, not just defaults.
  3. Decide and document the ADR==0 meaning, then lock that choice into the pipeline instead of leaving it as a sensitivity flag.
  4. Persist the chosen preprocessing + model as a loadable inference artifact so predictions come from loaded artifacts, not retraining.
  5. Consider pruning the 74-feature space further — many one-hot columns and possibly weak predictors are still in play.
